# Gap #7 — API-key redaction does not cover module loggers (P1, security)

**Status:** bugfix (restores a documented security property). **No new spec entry required**; the
spec 005 wording ("key redaction") already claims the property.

### Evidence (re-verified in the working tree)

- `src/openreview_cli/gateway/router.py:167-168` — `logging.getLogger().addFilter(_filter)`.
  A filter on a **logger** is consulted only for records the logger itself creates. Records from
  `getLogger("openreview_cli.xxx")` propagate **up** to root's handlers; root's logger-level filter
  is never consulted for them.
- `src/openreview_cli/app.py:228-264` — `_init()` creates the only two handlers in the process
  (`FileHandler` at `:244-246`, `StreamHandler` at `:247-250`) and adds **no** filter to either.
  `_init` runs from the `@app.callback` (`app.py:339,361`), i.e. on **every** CLI invocation.
- `src/openreview_cli/gateway/redaction.py:14-26` — the filter rewrites `record.msg` /
  `record.args` only; the module imports **only** `logging` (no `re`).
- Only effective call site today: the proactive `redact_key(creds)` at `router.py:197`.
- `tests/unit/test_api_key_redaction_e2e.py:45` exercises exactly that one call site, which is why
  the suite is green. (Its docstring cites `router.py:205` — **stale**; the call is at `:197`.)

**Second, subtler defect found while writing this plan** — `redact_key` masks only the *pattern
token*, not the key **value**:
`redact_key("sk-") == "***"`, so `"sk-testkey123456789"` becomes `"***testkey123456789"` — the key
body still leaks. Any test that asserts `raw_key not in log` passes trivially once "sk-" is masked,
while the secret is still readable. Task 7.3 addresses this.

### Change

**7.1 — attach the filter to root handlers (the required fix).**

`src/openreview_cli/gateway/redaction.py` (append after `RedactingFilter`, `:26`):

```python
import re  # add at the top — the module currently imports only `logging`

REDACT_PATTERNS: list[str] = [
    "OPENAI_API_KEY",
    "ANTHROPIC_API_KEY",
    "GOOGLE_API_KEY",
    "OPENROUTER_API_KEY",
    "COHERE_API_KEY",
    "HUGGINGFACE_API_KEY",
    "CUSTOM_API_KEY",
    "sk-",
    "sk-ant-",

def install_on_root_handlers() -> None:
    """Attach a RedactingFilter to every root handler (idempotent per handler).

    Handlers, not the root logger: propagated records never consult a logger's
    own filters, so a logger-level filter leaves module loggers uncovered.
    """
    for handler in logging.getLogger().handlers:
        if any(isinstance(f, RedactingFilter) for f in handler.filters):
            continue
        handler.addFilter(RedactingFilter(REDACT_PATTERNS))
```

**7.2 — redact exception text too (REQUIRED — its test is mandatory in B1A).** Today a traceback
carrying a key value reaches the handler unredacted, because `RedactingFilter` never looks at
`exc_info`. Extend `RedactingFilter.filter` (`redaction.py:19-25`) to pre-set a redacted `exc_text`:

```python
    def filter(self, record: logging.LogRecord) -> bool:
        record.msg = self._redact(record.getMessage())
        record.args = ()
        if record.exc_info and not record.exc_text:
            record.exc_text = self._redact(
                logging.Formatter().formatException(record.exc_info)
            )
        return True
```

**Mandatory, not optional:** this revision promotes 7.2 from "recommended" to required, because
`test_filter_redacts_exception_text` is part of B1A's named test set and the Batch 1 exit criteria
(§"Execution order"). **Red state is a `TypeError`, not an assertion failure:** before the fix
`record.exc_text` stays `None`, so `assert "ANTHROPIC_API_KEY" not in record.exc_text` raises
`TypeError: argument of type 'NoneType' is not iterable`. Keep that TypeError as the red evidence
(or assert on `logging.Formatter().formatException(record.exc_info)` first if a clearer message is
wanted), and say so in the commit body so a future reader does not "fix" it as a broken test.

**7.3 — value-level key redaction (now REQUIRED, reviewer-mandated).** Mask the key **body**, not
just its prefix. **The ordering matters and was wrong in the previous revision:** `"sk-"` is in
`REDACT_PATTERNS`, so if the literal-pattern pass runs first, `sk-live-abcdefghijklmn` becomes
`***live-abcdefghijklmn` and the value regex — which requires a literal `sk-` — can then never match.
The value regex must run **first**:

```python
_KEY_VALUE_RE = re.compile(r"\b(?:sk|pk|rk)-[A-Za-z0-9_\-]{12,}")
```

```python
    def _redact(self, text: str) -> str:
        # Value pass FIRST: the literal "sk-" pattern below would otherwise mask
        # the prefix and leave the whole key body in place.
        text = _KEY_VALUE_RE.sub(lambda m: redact_key(m.group(0)), text)
        for pat in self._patterns:
            if pat and isinstance(pat, str) and pat in text:
                text = text.replace(pat, redact_key(pat))
        return text
```

Verified behaviour (simulated against the real `redact_key`):

- `"using sk-testkey123456789"` → value pass first → `"using ***t***************"` (body gone).
  Under the old (literal-first) order it was `"using ***testkey123456789"` — body leaked.
- The `{12,}` bound is deliberate: `sk-abc123` (6 body chars) is untouched by the regex, so the
  existing `test_redacts_matching_string_in_record` assertion
  (`"Using OPEN**********=sk-abc123"`, patterns `["OPENAI_API_KEY"]` only) is **unchanged**.
- Cosmetic interaction (documented, not a bug): after the value pass, the already-masked form
  `sk-l***************` still contains the literal `"sk-"`, so the pattern pass re-masks the prefix to
  `***l…`. The key body stays gone; only the retained 4-char prefix is further mangled. **Do not**
  "fix" this by removing `"sk-"` from `REDACT_PATTERNS` — that would stop masking short keys
  (`sk-abc`) that the `{12,}` regex deliberately ignores.
- `"sk-ant-"` after `"sk-"` is **dead** (the `"sk-"` entry, applied first, consumes the prefix of any
  `sk-ant-…`); leave it in place as harmless documentation of intent, or note it in the commit body.

### Edge cases & risks

- **Idempotency / repeated `_init`.** `CliRunner` invokes the CLI many times in one process; `_init`
  replaces its own handlers (`app.py:240-243`), so the filter must be re-installed on the new
  handlers — `install_on_root_handlers()` is called *after* the handlers are added, so this is
  correct (a fresh handler has an empty `filters` list, so the `isinstance` guard does not skip it).
  Do **not** move the call before `root.addHandler`.
- **A second copy of the filter would be a no-op, not a leak** (it rewrites an already-redacted
  message), but the `isinstance` guard makes a second install impossible and the counter test pins
  one filter per handler anyway.
- **Intermediate frames.** A redaction filter must **never** drop a record (`filter` returns `True`
  always). Stage-1 "redaction" of `record.msg` and setting `record.args = ()` means `%`-style
  formatting is applied to the already-substituted text — the existing implementation already does
  this; keep it.
- **`record.exc_text` caching (7.2).** `Formatter.format` skips re-formatting when `exc_text` is
  already set, so a *stale* `exc_text` from a previous handler would be reused verbatim — harmless
  here because we set it to the redacted rendering.
- **Handler-filter interaction with the proactive call site.** Enabling the handler filter changes
  the logged form of the already-redacted key (`sk-t…` → `***t…`); the existing e2e positive
  assertion is updated accordingly (item 2 above). No raw secret is revealed in either form.
- **Test hygiene.** Any test that calls `install_on_root_handlers()` must restore the root handlers'
  filter lists in `finally` (see the first test's cleanup note — restore the snapshot; no marker to
  clean up). The reason is **not** that anything disables redaction for the rest of the run — `_init`
  rebuilds its own handlers (`app.py:240-250`), so later CLI invocations re-install normally. The
  reason is that the filter persists on **non-owned** root handlers (pytest's capture handler,
  plugins, `logging.lastResort`), where its in-place `record.msg`/`record.args` rewrite silently
  changes what other handlers — including `caplog` — render. See the Regression guard's B1A/`caplog`
  check.
- **TUI has no handlers.** The TUI configures no logging handler (grep: no `addHandler` /
  `basicConfig` under `tui/`), so records fall to `logging.lastResort`; the TUI log surface is out
  of scope for this gap. Note it in the commit message body if touching it becomes tempting.
- **Do not import `router` from `app.py`'s module scope** — it pulls litellm and would add ~4.5 s to
  every CLI invocation. `install_on_root_handlers` lives in the litellm-free `redaction.py` on
  purpose.
- **Blast radius:** `redaction.py` (+3 symbols: `REDACT_PATTERNS`, `_KEY_VALUE_RE`,
  `install_on_root_handlers`, plus `import re`), `router.py` (import line + `:138-148` + `:167-168`),
  `app.py` (1 import + 1 call). `router.py:167` was the only `RedactingFilter` construction site in
  `src/`; the remaining references are unit tests.

```python
@gateway_app.command("fallback")
def gateway_fallback(
    slot: str,
    model: str | None = typer.Argument(None, help="Backup model id, e.g. anthropic/claude-…"),
    clear: bool = typer.Option(False, "--clear", help="Remove the backup model for this slot."),
) -> None:
    """Set or clear the optional backup model for a slot (no fallback by default)."""
    from openreview_cli.config.loader import set_config_value
    from openreview_cli.config.paths import get_config_dir
    from openreview_cli.slots import PRIMARY_ONLY_SLOTS, VALID_SLOTS

    if slot not in VALID_SLOTS:
        typer.echo(f"Invalid slot '{slot}'. Valid slots: {', '.join(sorted(VALID_SLOTS))}", err=True)
        raise typer.Exit(code=1)
    if slot in PRIMARY_ONLY_SLOTS:
        typer.echo(
            f"Slot '{slot}' is primary-only — the gateway never uses a backup model for it.",
            err=True,
        )
        raise typer.Exit(code=1)
    if clear == (model is not None):
        typer.echo("Provide a model id, or --clear to remove the backup.", err=True)
        raise typer.Exit(code=1)

    config_path = get_config_dir() / "config.yml"
    try:
        set_config_value(
            config_path,
            f"gateway.models.{slot}.fallback",
            model if model is not None else "null",
        )
    except Exception as e:
        typer.echo(f"Error: {e}", err=True)
        raise typer.Exit(code=1) from None

    if model is not None:
        typer.echo(f"Backup model for {slot} → {model} (used only if the primary fails).")
    else:
        typer.echo(f"Backup model for {slot} cleared.")
```

```python
def discover_ollama(base_url: str = "http://localhost:11434") -> list[dict[str, Any]]:
    """Return locally installed Ollama models, or [] if the server is unreachable."""
    try:
        resp = httpx.get(f"{base_url}/api/tags", timeout=5)
        resp.raise_for_status()
        data = resp.json()
    except Exception:
        return []
    models: list[dict[str, Any]] = []
    for model in data.get("models", []):
        name = model.get("name", "")
        details = model.get("details", {})
        models.append(
            {
                "model_id": name,
                "slots": ["reasoning", "extraction", "graph"],
                "ram": None,
                "recommended": False,
                "status": "available",
                "note": f"Ollama local — {details.get('parameter_size', 'unknown')}",
            }
        )
    return models
```

```python
@gateway_app.command("models")
def gateway_models(
    provider: str,
    json_mode: bool = typer.Option(False, "--json"),
    no_discover: bool = typer.Option(
        False, "--no-discover", help="Skip querying a local Ollama server for installed models."
    ),
) -> None:
    """List available models for a provider."""
    from openreview_cli.gateway.models import ModelEntry
    from openreview_cli.gateway.registry import discover_ollama, load_registry

    registry = load_registry()
    p = registry.get(provider)
    if p is None:
        typer.echo(f"No provider '{provider}' found.", err=True)
        raise typer.Exit(code=1)

    if provider == "ollama" and not no_discover:
        for entry in discover_ollama():
            model_id = entry.get("model_id")
            if not model_id or model_id in p.models:  # bundled entries win
                continue
            p.models[model_id] = ModelEntry(
                slots=list(entry.get("slots") or []),
                ram=entry.get("ram"),
                recommended=bool(entry.get("recommended", False)),
                status=entry.get("status"),
                note=entry.get("note"),
            )
```

**Why in place, and why that is safe (verified, not assumed).** `ProviderInfo` is a plain pydantic
`BaseModel` (`gateway/models.py:26-35`): no `model_config = ConfigDict(frozen=True)`, and `models` is
an ordinary mutable `dict`. `load_registry()` has **no cache** — no `@lru_cache`, no module-level
memo; it rebuilds every `ProviderInfo` from the bundled JSON / user JSON / `config.yml` on each call
(`registry.py:45-78`). So `p` is *this invocation's own object*, `p.models[...] = ...` mutates nothing
that any other caller holds, and nothing is persisted (only `gateway refresh` writes `models.json`,
and it goes through `ModelRegistry`, a different class — see the out-of-scope note below).
The TUI's `@lru_cache(maxsize=1) _get_registry()` (`tui/domain/gateway.py:29-38`) caches its **own**
`load_registry()` result and is not on this code path. The previous `with_discovered_models(...)`
helper + `provider.model_copy(update=…)` copied the whole model dict to avoid mutating a shared
registry — that sharedness does not exist, so the copy was protecting against nothing.

Everything below (`if json_mode: …` at `:1498`, the table at `:1519-1540`) is unchanged — it already
reads `p.models`.

**2.3 — (optional) discovery notice.** When discovery runs and finds nothing, do **not** print an

that is the boundary reason the opt-out flag is kept rather than making discovery unconditional: a

**Explicitly out of scope:** `gateway refresh` (`:1566-1574`) writes the *bundled* `models.json`

# Gap #15 — `retrieve --top-k` above 20 is rejected (P2)

**Status:** bugfix (over-strict validation). **No new spec entry**, but the spec text documenting the
old rule must be updated — see §"Spec & doc updates".

### Evidence

  `if self.rerank_depth < self.top_k: raise ValueError(...)`.
