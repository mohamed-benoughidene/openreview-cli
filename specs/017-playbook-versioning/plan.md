# Implementation Plan: Playbook Versioning — 3-Position Playbook with Version-Stamped Storage

**Branch**: `feat/017-playbook-versioning` | **Date**: 2026-07-03 | **Spec**: `specs/017-playbook-versioning/spec.md`

**Input**: Feature specification from `/specs/017-playbook-versioning/spec.md`

## Summary

Add a 3-position playbook framework (Preferred/Acceptable/Walkaway + Amber for uncertain) with version-stamped storage in SQLite. Every playbook load creates an immutable version record keyed by `(id, version, content_hash)`. Review reports reference the frozen playbook version via `<id>@<version>` format. Existing `precheck-nda-v1.yaml` and two new bundled playbooks ship with version `1.0.0`. Content changes without version bumps get a `+N` suffix. All work uses stdlib (`hashlib`, `sqlite3`) and existing deps only — no new third-party packages.

## Technical Context

**Language/Version**: Python 3.12

**Primary Dependencies**: `pyyaml` (existing — YAML parsing), `hashlib` (stdlib — SHA-256 content hash), `sqlite3` (stdlib — version storage), `dataclasses` (stdlib — Position3/PlaybookRecord models)

**Storage**: SQLite via existing `src/openreview_cli/storage/` layer (C-03). Two new tables: `playbook` (metadata) and `playbook_version` (immutable version rows). Existing `review/playbooks/` YAML files remain the authoritative source.

**Testing**: pytest with existing patterns — `tests/unit/` for model/data-layer tests, `tests/integration/` for CLI command tests. TDD per AGENTS.md.

**Target Platform**: Linux, macOS, Windows (CLI tool only)

**Project Type**: CLI tool (single-party review pipeline)

**Performance Goals**: Playbook YAML load < 500ms, SHA-256 hash computation < 100ms, SQLite insert < 50ms. Playbooks are < 50 KB (Assumption 3).

**Constraints**: 
- < 100 MB peak memory (constitution §III) — playbook YAML is tiny, loaded lazily at review time
- Local CLI only — no server, no daemon (constitution §II)
- No new third-party deps — all additions are stdlib (constitution §IV)
- TDD — tests written before implementation code
- Single-party scope only (§6.7, R-7) — no bilateral comparison

**Scale/Scope**: 3 bundled playbooks (PreCheck, DealCheck, HireCheck) + unlimited user-supplied custom playbooks. Each playbook < 50 KB. SQLite storage overhead is negligible (\~1 KB per version row + full YAML content).
